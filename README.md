## Создание новой ветки

1. Перед созданием ветки всегда возвращайтесь на main и обновляйте её, чтобы не пропустить чужие или свои прошлые слияния:
   git checkout main (перейти на ветку)
   git pull origin main (скачать последние изменения)

2. Создайте новую ветку (например, имя_название страницы) и сразу переключитесь на неё:
   git checkout -b home (создать и переключиться на новую ветку)

3. В процессе или в конце работы сохраняете изменения локально (коммитите):
   git add .
   git commit -m "Сверстал страницу "

4. Отправляете эту ветку на GitHub:
   git push origin название ветки

## Слияние (Merge) через Pull Request на GitHub

1. Зайдите на сайт GitHub в свой репозиторий.
2. Нажмите появившуюся желтую кнопку Compare & pull request (или зайдите в раздел Pull Requests -> New Pull Request).
3. Проверьте направление: base: main ← compare: home.
4. Нажмите Create pull request.
5. Если конфликтов нет (горит зеленая галочка), нажмите Merge pull request, а затем Confirm merge.
6. Готово! Ветка слита с main на GitHub.

## Переход к следующей странице

После того как вы нажали фиолетовую кнопку Merged на GitHub, возвращайтесь в терминал VS Code:

1. Переключитесь обратно на главную ветку:
   git checkout main

2. Обязательно скачайте только что слитую страницу с GitHub на свой компьютер:
   git pull origin main

3. Создайте ветку для следующей страницы:
   git checkout -b название ветки.

## Наименовании файлов и папок

- **Файлы:**

1. Все создаваемые файлы с расширениями `.jsx`, `.js`, `.css` и т.д., а также любые крупные файлы, называем **с большой буквы** (например, `Button.jsx`, `Styles.css`).

- **Папки:**
  1. Глобальные общие папки можно называть **с маленькой буквы** (например, `pages`).
  2. Вложенные в них папки разделов или компонентов пишем **с большой буквы** (например, внутри `pages` будут `Home`, `Shop`, `Service`).

## Отмена действий и исправление ошибок

Если что-то пошло не так.

1. git commit --amend -m "новое сообщение" — исправить текст последнего коммита (если опечатались).
2. git restore <имя_файла> — отменить все несохраненные изменения в файле и вернуть его к состоянию последнего коммита.
3. git reset --hard HEAD — уничтожить все незакоммиченные изменения на компьютере и вернуть проект к последнему сохраненному коммиту (аккуратно, код сотрется навсегда!).
4. git merge --abort — прервать слияние веток, если вы начали делать git merge, вылезли страшные конфликты, и вы хотите вернуть всё как было до слияния.
